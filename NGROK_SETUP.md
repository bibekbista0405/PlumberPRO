# PlumbPro single-port ngrok setup

## Terminal 1
From the `backend` folder:

```powershell
npm install
npm run dev
```

`npm run dev` builds the React frontend and starts the API on port 5000.

## Terminal 2

```powershell
ngrok http 5000
```

Open the HTTPS URL generated by ngrok. The same URL serves the React frontend and `/api/*`.

The frontend API client uses `/api` by default, so it does not call `localhost:5000` from the browser.

If frontend source files are changed, restart `npm run dev` to rebuild the production frontend bundle.

## Why the frontend loaded but API calls didn't work

ngrok's free tier shows an HTML "you're about to visit..." interstitial page in front of browser traffic to a tunnel URL, before letting the real request through. Visiting the site in a normal browser tab looks fine because you click "Visit Site" once and move on — but calls made by the page's own JavaScript (`fetch`) can still get served that interstitial HTML instead of real JSON, since ngrok can't always tell those apart from a fresh visit. The API call technically "succeeds" (HTTP 200) but the body is a warning page, not data, so the app looks like the backend is doing nothing.

The frontend now sends the `ngrok-skip-browser-warning` header on every API request, which tells ngrok to skip the interstitial for that request. This header is harmless when you're not using ngrok (e.g. in production behind a real domain), so nothing else needs to change.
